## ADDED Requirements

### Requirement: 房间大厅必须支持开始闸门
MUST:房间服务必须提供开始房间的显式状态机入口，用于校验房主权限、房间状态、成员准备状态和连接状态，并在通过后将房间推进到第一阶段占位开始状态。

#### Scenario: 房主开始已准备房间
- **WHEN** 当前房主请求开始开放房间，且除房主外所有在线成员都已准备
- **THEN** 房间服务必须将房间状态迁移到已开始状态并返回最新房间快照

#### Scenario: 非房主请求开始
- **WHEN** 非房主成员请求开始房间
- **THEN** 房间服务必须拒绝请求并保持房间状态不变

#### Scenario: 成员未准备
- **WHEN** 房主请求开始房间，但存在未准备的非房主在线成员
- **THEN** 房间服务必须拒绝请求并保持房间状态不变

#### Scenario: 成员断线
- **WHEN** 房主请求开始房间，但存在断线保留中的成员
- **THEN** 房间服务必须拒绝请求并保持房间状态不变

#### Scenario: 房间已关闭或已开始
- **WHEN** 调用方请求对关闭或已开始房间执行开始操作
- **THEN** 房间服务必须拒绝请求并保持房间状态不变

### Requirement: 房间开始闸门不得承载战斗模拟
MUST:房间开始闸门只表达大厅流程通过校验并进入第一阶段占位开始状态，不得实现高频战斗同步、服务端权威模拟、战斗结算、观战、回放或 battle server 调度。

#### Scenario: 需求需要正式战斗
- **WHEN** 后续需求要求进入正式战斗模拟、结算、观战或回放
- **THEN** 项目必须创建独立 battle server 或战斗流程 OpenSpec change
